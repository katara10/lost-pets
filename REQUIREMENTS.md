# Требования к проекту: Lost Pets

## 1. Общая информация
* **Название проекта:** Lost Pets (Поиск потерянных животных)
* **Тип проекта:** Full-stack веб-приложение (MVP)
* **Стек технологий:** React + TypeScript (Frontend), Python + FastAPI (Backend), PostgreSQL + SQLAlchemy (База данных).

## 2. Цель и назначение
**Цель:** Создать платформу для помощи в поиске потерянных и найденных животных, объединяющую владельцев и неравнодушных людей.
**Назначение:** Предоставление пользователям инструментов для публикации объявлений, указания геолокации, генерации и печати листовок, а также быстрого распространения информации в социальных сетях.

---

## 3. Функциональные требования (ФТ)

### 3.1. Управление пользователями и авторизация
* **ФТ-01.** Система должна обеспечивать регистрацию новых пользователей (по email и паролю).
* **ФТ-02.** Пароли должны храниться в БД только в виде стойких криптографических хэшей.
* **ФТ-03.** Система должна реализовывать аутентификацию с помощью JWT (выдача access и refresh токенов).
* **ФТ-04.** Система должна обеспечивать обновление access-токена по действующему refresh-токену.
* **ФТ-05.** Система должна поддерживать выход из аккаунта (отзыв refresh-токена текущей сессии и очистка состояния на клиенте).

### 3.2. Работа с объявлениями (CRUD)
* **ФТ-06.** Любой пользователь (в т.ч. неавторизованный) должен иметь возможность просматривать ленту всех активных объявлений.
* **ФТ-07.** Система должна поддерживать фильтрацию объявлений по типу (потеряно/найдено), виду животного и городу.
* **ФТ-08.** Авторизованный пользователь должен иметь возможность создать объявление, указав: тип, вид животного, кличку, описание, место (адрес), дату, контакты и прикрепив фотографии.
* **ФТ-09.** Автор объявления должен иметь возможность редактировать и удалять свои объявления.
* **ФТ-10.** Автор должен иметь возможность изменять статус объявления (Активно / Найдено / Закрыто).

### 3.3. Дополнительные возможности
* **ФТ-11.** Система должна генерировать шаблон листовки (формат А4) с данными объявления и фото для последующей печати.
* **ФТ-12.** Пользователь должен иметь возможность поделиться объявлением (копирование ссылки в буфер обмена или шаринг в соцсети).

---

## 4. Нефункциональные требования (НФТ)

### 4.1. Технические ограничения
* **НФТ-01. Стек:** Строгое соблюдение обязательного стека (React, TypeScript, FastAPI, PostgreSQL, SQLAlchemy).
* **НФТ-02. Архитектура Frontend:** Применение упрощенной методологии Feature-Sliced Design (слои `app`, `pages`, `widgets`, `features`, `entities`, `shared`).
* **НФТ-03. Архитектура Backend:** Разделение кода на роуты (API), схемы валидации, модели БД и бизнес-логику.

### 4.2. Интерфейс и UX
* **НФТ-04. Адаптивность:** Интерфейс должен корректно отображаться и быть удобным на мобильных устройствах (от 375px), планшетах (768px) и десктопах (1440px+).
* **НФТ-05. UI-библиотека:** Использование Material UI (MUI) для обеспечения единого стиля и читаемости элементов.
* **НФТ-06. Обратная связь:** Наличие визуальных состояний загрузки (лоадеры), пустых состояний (нет данных) и понятных сообщений об ошибках валидации.

### 4.3. Безопасность и качество кода
* **НФТ-07. Безопасность:** Защита от CSRF/XSS, настройка CORS на бэкенде.
* **НФТ-08. Секреты:** Конфигурационные данные (пароли БД, JWT-секреты) должны храниться в переменных окружения (`.env`), которые исключены из репозитория через `.gitignore`.
* **НФТ-09. История разработки:** Наличие осмысленной истории коммитов в Git (соответствие Conventional Commits приветствуется).
* **НФТ-10. Документация:** Наличие файлов `README.md` и `REQUIREMENTS.md` с актуальными инструкциями по запуску и описанием проекта.

---

## 5. Ограничения проекта (Out of Scope для MVP)
Следующие функции не входят в рамки первого семестра:
* Интеграция с реальными картографическими сервисами (Яндекс.Карты, Google Maps) — только текстовый адрес.
* Прямая отправка SMS или Email уведомлений (работает только отображение контактов).
* Чат между пользователями внутри приложения.
* Сложная система модерации и жалоб на контент.
